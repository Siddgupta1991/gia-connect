# GIA Connect

A complaint tracking app for the **Govindpura Industrial Association (GIA), Bhopal**.
Industry owners raise civic complaints (roads, water, dead animals, parking), the association President (Admin) sets severity, adds the right people and drives each complaint to closure. Every complaint has a private chat, and the chat is **permanently deleted** when the complaint is resolved.

Built with Expo (SDK 58), React Native 0.88, TypeScript (strict) and React Navigation 7. One codebase for Android and iOS.

## Download the Android app (APK)

1. Open the **Releases** page: https://github.com/Siddgupta1991/gia-connect/releases
2. Under the latest release (`GIA Connect 1.0.0 (build N)`), download `gia-connect-1.0.0.apk`.
3. Open it on an Android phone. If asked, allow "Install unknown apps" for your browser or file manager.

Every push to `main` builds a new APK with GitHub Actions and publishes it as a new release. You can also start a build by hand: **Actions > Android APK > Run workflow**.

The APK is a release build **signed with the default debug key**. That is fine for testing. It cannot be uploaded to the Play Store (see "Play Store release" below).

## What the app does

- **Members** raise complaints in two steps (category and sub category, then location and description). If an open complaint already exists for the same category at the same place, the app suggests joining it ("me too") instead of creating a duplicate.
- **Admin** sees every complaint, a dashboard, filters, hotspots, sets severity and status, adds people to a complaint, resolves with "Resolve now" and sends custom notifications to everyone, members, moderators, selected people, or everyone in one complaint, with a sent history and read counts.
- **Moderators** see only complaints they were added to, chat, and move them from Open to In progress to Fixed.
- **Visibility rule**: a complaint is visible only to the person who raised it, every admin, and people added to it (or who joined it). This is enforced in the data layer (`src/domain/visibility.ts`, `src/domain/engine.ts`), not only in the screens.
- **Lifecycle**: Open > In progress > Fixed > Resolved. The complainant confirms a fix or reopens it with a reason. Admin can resolve at any time after a confirmation dialog.
- **Chat deletion**: when a complaint is resolved, every message (text and system) is hard deleted. The complaint record stays for history and hotspots, and the thread shows "This conversation was deleted because the issue was resolved."
- **Notifications** are in app only (Alerts tab with an unread badge). Nobody is ever notified about their own action. No WhatsApp or SMS.

## Build the APK yourself

### Route A: EAS Build (cloud, needs a free Expo account)

```bash
npx eas-cli@latest login
npx eas-cli@latest build --platform android --profile preview
```

The `preview` profile in `eas.json` produces an installable APK. The `production` profile produces an AAB for the Play Store.

### Route B: local Gradle build

Needs the Android SDK and **Java 17** (newer Java versions are not supported by the Android Gradle plugin).

```bash
npx expo prebuild --platform android
cd android && ./gradlew assembleRelease
# APK: android/app/build/outputs/apk/release/app-release.apk
```

The `android` and `ios` folders are generated by Expo and are not committed. Change native settings in `app.json`, never by editing those folders.

### Route C: GitHub Actions (set up)

`.github/workflows/android-apk.yml` runs on every push to `main` and on manual trigger. It installs dependencies, runs type check, lint and tests, runs `expo prebuild`, builds `assembleRelease` with Java 17, uploads the APK as a workflow artifact and publishes a GitHub Release with the APK attached. It builds the ARM ABIs only (arm64-v8a and armeabi-v7a), which covers real phones.

## Play Store release (later)

1. Create an upload keystore once and keep it safe (never commit it):
   ```bash
   keytool -genkeypair -v -storetype PKCS12 -keystore gia-upload.keystore -alias gia-upload -keyalg RSA -keysize 2048 -validity 10000
   ```
2. Easiest path: let EAS manage signing. Run `npx eas-cli@latest build --platform android --profile production`, and EAS will create or use your keystore and output an AAB.
3. Or with GitHub Actions: store the keystore (base64) and passwords as repository secrets and add a signing config through a config plugin or `expo-build-properties`.
4. Bump `version` and `android.versionCode` in `app.json` for every store upload.

## Stage 2 plan: shared backend (not built yet)

The screens only talk to the `Repository` interface (`src/data/repository.ts`). Stage 2 adds a `SupabaseRepository` with the same methods and swaps one line in `src/data/index.ts`.

**Planned tables (Postgres on Supabase)**

| Table | Columns |
|---|---|
| `profiles` | `id` (= `auth.users.id`), `username`, `name`, `mobile`, `industry_name`, `plot_no`, `role` (`member` / `moderator` / `admin`), `created_at` |
| `complaints` | `id`, `number` (sequence from 101), `category`, `sub_category`, `location`, `location_key`, `description`, `severity`, `status`, `created_by`, `created_at`, `updated_at`, `resolved_at`, `resolved_by`, `chat_deleted` |
| `complaint_participants` | `complaint_id`, `user_id`, `kind` (`creator` / `added` / `joined`), `added_by`, `created_at` |
| `messages` | `id`, `complaint_id`, `sender_id` (null for system), `kind`, `text`, `created_at` |
| `notifications` | `id`, `to_user_id`, `kind`, `title`, `body`, `complaint_id`, `broadcast_id`, `created_at`, `read_at` |
| `broadcasts` | `id`, `sent_by`, `title`, `body`, `audience`, `complaint_id`, `created_at` |
| `broadcast_recipients` | `broadcast_id`, `user_id` |
| `push_tokens` | `user_id`, `expo_push_token`, `platform`, `updated_at` |

**Security**: Row Level Security mirrors `visibility.ts`. A complaint row is readable when the user is an admin or has a row in `complaint_participants`. Messages follow their complaint. Role changes and status moves go through Postgres functions (RPC) that call the same rules as `lifecycle.ts`, so a client cannot skip them. Resolving runs in one transaction that deletes the messages and sets `chat_deleted`.

**Push notifications**: register with `expo-notifications`, save the Expo push token in `push_tokens`, and send pushes from a Supabase Edge Function triggered on insert into `notifications` using the Expo Push API. Android delivery goes through Firebase Cloud Messaging, so an FCM project and `google-services.json` (kept out of git, added as an EAS secret) are needed. iOS needs an APNs key in the Expo account.

**Other Stage 2 items**: real authentication (Supabase Auth with phone OTP, no plain text passwords), admin screen to promote a user to Moderator, Realtime subscriptions for live chat.

## Decisions made on your behalf

- **React Navigation** (native stack and bottom tabs) instead of Expo Router, for a simple role based tab setup.
- **Admin acting on a complaint joins its thread**, so the admin then gets that complaint's chat and status notifications. Other admins still see every complaint but are not notified about every message.
- **Anyone in a thread may add people** while the complaint is open (section 5 rule). Members see "Add people" in the menu.
- **Admin may also reopen** a Fixed complaint; the complainant must give a reason to reopen.
- **"Set severity" and "Change status"** open the same sheet (section S10). The status sheet only offers forward work moves; closing is done with "Resolve now" or "Confirm fix".
- **Members who join a complaint ("me too")** can see and chat in it, but only the original complainant confirms the fix.
- **Similar reports** hide complaints you raised or already joined. The match is same category plus same normalised location (lowercase, trimmed, single spaces).
- **Hotspots** count unresolved complaints only. Hotspot detail shows the full timeline at that place, including resolved ones.
- **Admin tab labels** are "Home" and "Issues" (instead of "Dashboard" and "Complaints") so five labels fit at 13 pt on a 360 pt wide phone. Screen titles still say Dashboard and All complaints.
- **Hint and timestamp text** uses `#78716C` instead of `#A8A29E`, because `#A8A29E` on white fails WCAG AA contrast. `#A8A29E` is still used for the "Not set" severity dot and borders.
- **APK** is built for ARM ABIs only, to keep it smaller and the build faster.
- **App icon** is a white "G" on indigo, generated by a script.
